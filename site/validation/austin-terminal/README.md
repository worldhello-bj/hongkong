# AUS F 精确终点的保守连通性预检

## 范围与结论

原请求保持为柯士甸 D2 → F 楼梯口：2026-10-13 香港时间 11:00、扶梯优先、不含出租车。起点为 `AUS:N:7144fc7f1bf80b`，终点为 `AUS:N:4ab0a937f564e0`。F 升降机入口是另一处终点，未被替换进来。

当前已载入来源里，F 属于七节点、六条实体楼梯的孤立部分。新预检证明的是“当前模型没有完整连接”，不是现实不可达。扶梯优先仍是软偏好，楼梯没有因此被一律排除。

## 为什么能够提前结束全部公共方式比较

预检使用 area、station、detail 三份来源的有向边并集，并把禁用、关闭、付费区、设施限制和时刻规则全部放宽。它从精确 F 节点反向遍历所有可以进入终点的来源边，得到保守超集。

仅在同时满足下列条件时返回来源连接缺失：

- 精确起点不在终点反向闭包内。
- 闭包内没有可被匿名公共站点步行接入投影使用的官方室外路段。
- 闭包内没有外部公共接入锚点，包括 area 入口、旧/新入口别名、地铁来源目标、公共班次站点、预计算步行连接端点、站内接续端点。
- 三份图、服务与缓存资料完整，来源身份和坐标一致，且实际入口解析器、Worker 与后备路线的行为匹配已审查指纹。

公共交通只能把行程带到接入锚点；其最后一段仍必须从锚点或室外投影走进精确终点。这七个节点没有上述任何入口，因此增加公交、电车、地铁班次，或放宽全部运行时间，也无法在当前模型里接入 F。动态详细图和演示后备路线保留精确节点，不能凭附近位置增加一条连接。

这不是只看单份静态图的连通分量，也没有把等待超时改写为 NO_ROUTE。

## 保守退回与取消

本优化只覆盖同站、两个单一精确来源入口、完整公共方式、不含出租车的请求。跨站、普通地图点、多锚点、未知图/策略、无效日期、缺少详细图、发现可能接入点或较大反向闭包时，都继续原有路由。

详细图没有就绪时不为本优化额外下载资料。原有后台详细图加载和 `pendingDetailRefresh` 流程照常工作：早发请求先进入原路由，资料就绪后旧代际取消并重新规划。

完整图校验、不可变性验证和边扫描分块执行，检查目标为约 4 ms，每块最多 2,048 条记录；JavaScript 分配或 GC 不能被检查点强制抢占。取消或新请求会停止旧证明，旧结果不发布。证明异常退回原搜索。

最终实现使用稳定的小请求快照与不可变的公共接入字段快照，包括嵌套站台目标。终点闭包不缓存，避免请求切换污染下一次证明。仅缓存对同一不可变来源图已完成的结构校验。
